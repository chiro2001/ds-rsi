# 记忆译码课程与反事实损失

真实四芯片 A/v2 的首1,000微批共消费1,165,012学生输入token、57,772保持教师token，执行250个优化器步。32个独立中英文事实/位置查询的标准单token自由回忆EM为9.375%，代码事实为0，16个反事实对均未同时答对；实体编号置换挑战EM为6.25%。M5 未通过，不能进入B能力阶段。

诊断对相同事实比较源 batch/独立编码、候选1/8、训练/开发问题模板以及 native/canonical teacher forcing。平均CE差异最大约0.035，第一关键token仍常错误，即使仅给支撑记录也未能可靠译码。平均CE被答案的共用格式与后续确定词汇稀释，不能代表记忆内容可用。原始结果见 reports/ab-A-v2-1000-*.json。

`ab-v3-random-entity-order` 在保持反事实问题、负例、支撑ID/位置不变的前提下，随机置换所有近似实体编号，目标不再固定为最小编号。v1/v2 实施文件与数据身份保持原样，可显式恢复；v3 单独保存实施指纹和世界命名空间。

新课程先用单条 oracle 支撑训练内容译码（`--curriculum facts --memory-candidates 1`），同世界负例仍编码入M池，保持样本仍包含干扰。通过随机代码自由回忆与内容消融后，再升到2/4/8候选，混合位置/更新/经历任务，随后进入实际寻址。这些阶段不减少最终要求；单条oracle达标仅是读写译码中间门槛。

反事实损失在两个答案的第一个不同token之前计算。同问题和共同答案前缀完全相同，两条分支仅改变选中记录的完整 payload，原ID、地址、时间和来源保持不变。该不同token作为目标被评分，不作为输入，也不写入M：

`L_cf = softplus(margin - (log p(y | M_actual, common_prefix) - log p(y | M_counterfactual, common_prefix)))`

学生损失在已有事件平均回答CE上加 `counterfactual_weight * L_cf`，保留原语言保持损失。无支撑、缺失证据及保持任务不开启这一项。对两种分支使用同样长的 prefix，避免不同数值形状形成伪对照；两个源编码和两个额外 prefix 的实际输入token均计入学生账本。

CF目标并不单独保证整个答案正确，必须继续做 answer-free EM 和反事实成对评分。`oracle_foreign` 保持 oracle 的选择，仅用相反世界替换全部选中payload；候选数在报告中明确，不能把 top1 当作 top8 或实际寻址验收。

配置与损失固定在 checkpoint 身份中。旧默认8候选、无CF的运行保持原身份格式。数据/课程更改使用新 run 和显式 `--init-from` 的 A→A 权重初始化，记录来源manifest及进度，并重置该新 run 的优化器、梯度、RNG与游标；原 run 完整训练态保留。这是课程转换，不是精确恢复。继续同一 run 只使用完全相同参数和 `--resume`。

正式A预算仍按各A run来源链累计学生实际输入，不能因新 run 计数重置而遗忘此前消耗。当前v2已用1,165,012，下一A run上限为剩余28,834,988；先分批保存、独立评测和诊断，不把预算耗尽当作能力达标。
