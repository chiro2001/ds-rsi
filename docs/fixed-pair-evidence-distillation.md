# 固定候选多问题与证据条件蒸馏 v7

2026-10-26。借鉴D2L的行为蒸馏与组合训练；本轮保持已有Writer/Reader及原GDN/eager，不实现动态LoRA或复现完整D2L。正式训练需先完成CPU/CI、CUDA参考/前缀复用与独立进程恢复验证。

## 数据与候选

显式revision为`ab-v7-fixed-pair-qa`。保留v6的40%保持题及其自然续写、普通保持规则；其余事实episode一次编码源记录，提供两道问题。约半数世界分别询问两个实体，另一部分询问同一实体的校验码与箱封码。每个问题独立清空工作状态，只保留写出的记忆。

双候选时两道问题使用相同的源顺序候选ID，不能根据support标签重排或替换候选。两道问题分别指向其中一条记录，因此正负记录的新旧与位置在这个任务内对称。单候选复习时则显式给各题正确单记录，作为内容译码练习。沿用按世界哈希的single-double-world-v1，两种证据变体共享候选分配。

训练事实含完整码和原v5按位辅助题。两个反事实版本保持实体、属性、问题、时间、候选和所有负记录不变，只改变两条支撑记录的一个字符，各题标签跟随改变。附加源码布局变体用于独立压力测试，首批正式使用native布局。训练/开发/测试的世界和问题表述分开。

标签只进入损失与评分。`fixed_memory_candidate_ids`指定同一记录集合，不携带哪条属于当前问题的选择；模型实际输入仍是原生源事件与无答案的问题前缀。教师原文不会拼入学生前缀，教师回答不写入M。

## 目标函数

保留每题CE、首次分歧位置的内容反事实损失及原保持目标，移除先前RS1支撑attention辅助，新增权重为1的证据条件top32+tail KL：

`L_fact = mean_question(CE + CF + evidence_weight * accepted_teacher_KL)`

教师使用同一冻结底座、关闭记忆，看到当前题的正确原文和问题。用标准单token缓存路径先自由贪婪生成；只有所有目标token及EOS精确一致时才接受。不是根据teacher-forcing低NLL或解码后的近似字符串启用。成功轨迹上的教师top32和tail概率用于学生回答位置，含EOS。

单候选与保持题不调用此证据教师；保持题继续沿原v6规则监督。教师筛查在no_grad中进行，立即释放缓存，只保留稀疏分布。与学生共享底座权重，不额外常驻一个大模型。两道学生查询的梯度图仍需实际测显存，不能由模块大小推断峰值。

Student账本包括全部源编码、反事实源编码、回答前向及两个反事实前缀。Teacher账本包括筛查时真正处理的原文/问题及已消费生成token；EOS被预测但不再作为输入。未通过教师筛查仍记录其计算成本，并回退原CE/CF，不把错误教师强加给学生。
