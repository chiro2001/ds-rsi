## 5. 必须带入新项目的教训

### 5.1 已有直接证据的实现问题

- 首轮预训练前约 6500 步的 Engram 表实际冻结：门控与梯度过小，普通 SGD 更新低于 fp32 表权重的可表示精度。后续归一化与行尺度自适应更新让表开始移动。
- 压缩注意力曾只在索引器打分时施加因果掩码，最终注意力重新计算 logits 后没有复掩；top-k 超过可见槽数时读入未来。该问题在 2026-09-27 修复，SFT v3 与后续补训基于修复后的路径，但它们继承了受影响的 base。
- `ced_kv` 的计算没有接入消费路径。`ced_enabled`、调用次数和形状检查不足以证明模块有效。
- 文档隔离仍有结构缺口：原始 SWA 有文档掩码，压缩池化没有文档输入，压缩槽可见性只判断时间；Engram 的 n-gram 也没有文档边界输入。新实现需要覆盖这些路径，验证前一文档的变化不会影响后一文档的独立预测。
- 多卡 Engram 梯度同步会稠密化，再转回稀疏布局；当前小表可以跑通，更大表的通信和显存成本需要重新设计与实测。
- 原始推理依赖整段重算。增量推理需要显式维护槽的起止位置、文档归属、共享 KV 的来源与部分压缩块状态，不能继续用本次输入长度反推全部缓存语义。

### 5.2 报告中的根因推断需要降级为待检验假设

- `world_fact` 上答对题，可能使用主干权重、embedding、Engram 或其组合。无上下文问答测的是参数化事实回忆；需要关闭、置乱或替换 Engram 的消融，才能归因其贡献。
- 中文答案位置最后 2–4 个 token 不含实体，确实会妨碍直接局部查表，但实体位置的 Engram 输出仍可能经注意力传递；这不足以单独证明中文失败的唯一根因。
- “每行信噪比约 1:1221”来自平均访问次数估算，没有直接测量梯度方向、大小及多头组合的解码能力。碰撞干扰是候选解释，需要受控实验。
- 表更新幅度不足已被旧项目后续位移实测否定；stage10 的 facts×6 / 1B token 旧配方失去原先依据。`NEXT_WINDOW_PLAN.md` 自身也撤回了这个建议，尾部旧配方仍留在文件中。
- “非 facts 数据几乎不更新表”的旧结论，与后续测到 0% facts 阶段表仍移动的结果冲突，不能用于假定知识永久保留。
- 早期隐状态检索实验只覆盖当时的模型与训练方式；旧交接报告已指出若干结论不能外推到带训练索引器、Engram 的新结构。

## 7. 新模型的初步设计方向：待对齐

若继续原始端侧目标，建议明确区分三个可独立验证的部分：

1. **语言与上下文主干**：因果注意力、训练与增量推理共用状态定义；CSA2 的可学习压缩、共享 KV 与索引器逐项落地。GDN/SWA 混合、GR、MoE、CED 分别做成本和能力消融，再确定最终组合。
2. **世界知识参数表 W**：保留条件查表思路，比较现有平均池化与保留各头信息的读取方式；测量门控贡献、事实学习、碰撞与遗忘，保证开关消融可执行。
3. **跨会话可写记忆 M**：明确写入内容、寻址键、时间信息、冲突处理及读取注入；训练读写路径和跨段梯度，先验证写后读、改写问法、更新与干扰，再讨论长期存储规模。

“参数持续更新”“外部记忆持续写入”“推理状态持续保留”需要各自定义训练方法与成功判据。原项目的手机目标、最终尺寸和这些能力的优先级需要用户重新确认。

建议执行顺序：正确性与状态接口 → 小规模干净基线 → W/M 受控消融 → 扩大预训练与 SFT → 量化和端侧实现。新的参数量与 token 预算根据可用算力和实际吞吐确定。
