# 持续上下文与可写隐空间记忆：结构提案 v0.1

日期：2026-10-09。状态：讨论稿，尚未实现或验证。
目标：持续处理没有预设总长度上限的经历流，保留可写、可寻址的隐空间记忆，并允许远期信息逐步模糊。
依据：[旧项目探索](legacy-audit.md)，以及旧项目关于 bounded replay、隐状态检索、记忆训练和压缩的实验记录。

已对齐的取舍：隐空间存储本身允许逐渐丢失细节；harness 提供模型可直接读写、修改、删除的显式明文记忆，并提供上下文历史检索工具。语言底座优先考虑沿用已有权重，训练成本见 [预训练与微调预算](training-budget-v0.md)。

首个底座已选择 Qwen3.5-0.8B；具体接入层、模块尺寸与缓存改造见 [0.8B 结构提案](qwen35-08b-memory-architecture-v0.md)。

首轮样本、损失与 50M token 课程预算已细化到 [训练协议](training-protocol-v0.md)，并附有语义样例与 tokenizer 模板核验。

## 1. 需要定义的能力

持续上下文应成为模型的流式状态接口：新一轮对话沿用旧状态，新的经历改变状态，运行中断后可恢复同一状态。长期记忆应支持一次写入、未来改写问法读取、信息更新、时间关系与多段推理。

有限存储无法无损保留无限随机信息。可实现的目标是：运行可以持续延长；活跃内存有界；长期档案可以增长，或者在固定容量下压缩与遗忘；记忆质量随保留策略、压缩深度和干扰量变化。远期模糊应由这些机制产生，并能够测量。

不把整个无限序列继续装入全局 KV，也不把全部历史反复压进一个向量。建议同时保留不断演化的工作状态和可寻址的经历档案。

## 2. 状态与模型接口

一个实例的运行状态包含：

```text
LifeState = {
    recent_kv,              # 有界的最近上下文
    recurrent_state,        # 工作状态，含多种时间尺度
    memory_store,           # 历史隐空间记录与层级摘要
    memory_index,           # 时间、语义、可选词法锚点索引
    active_memories,        # 本次任务正在读取的少量记忆
    logical_clock,          # 已处理的输入/生成位置
    write_cursor,          # 尚未提交的段及提交位置
    explicit_memory_ref,   # harness 显式记忆的引用/版本
    history_cursor,        # 可查询经历历史的当前边界
    model_and_codec_version
}
```

外部接口建议：

```text
step(token_or_event, life_state) -> prediction, new_life_state
forward_chunk(tokens, life_state) -> predictions, new_life_state
snapshot(life_state) / restore(snapshot)
```

分块只改变执行方式，不能隐式重置状态。读写节奏由全局逻辑位置和已发生事件决定，不能随着调用者任意切块而改变。新会话接续已有实例；清空状态和建立分支应是显式操作。

模型版本与记忆编码器版本必须记录。更换权重后，旧隐空间记录未必仍可读，需要兼容适配、迁移或冻结记忆编码空间。

## 3. 推荐结构：局部注意力、递归状态、外部隐空间档案

| 部分 | 作用 | 保存的信息 | 资源增长 |
|---|---|---|---|
| 最近上下文 C | 精确处理正在发生的对话与任务 | 最近 W 个 token 的 KV | O(W) |
| 工作状态 S | 延续当前主题、任务、指代和缓慢变化的状态 | 多个时间尺度的递归状态 | 配置固定 |
| 经历档案 M | 召回已经离开窗口的具体经历 | 每段多个 latent slot，加时间、地址、来源 | 随档案增长或按预算压缩 |
| 层级摘要 | 组织远期经历、粗筛相关时段 | 多段经历的可学习 latent 摘要 | 与档案策略有关 |
| harness 明文记忆 E | 模型主动决定记住、修改或遗忘的信息 | 可读写的文本记录 | 由独立存储策略控制 |
| harness 上下文历史 H | 按需查找已经发生的上下文 | 带来源和时间的历史记录 | 档案容量与索引独立管理 |

主干候选为 SWA + GDN 风格递归状态。S 的固定容量用于工作连续性；M 的独立记录用于较可靠的具体回忆。两类状态都参与生成，彼此的贡献分别做消融。层比例、状态尺寸与读模块层位通过小规模实验确定。

W（通过训练得到的世界知识参数表）可以另行保留，M 不需要沿用 W 的局部 n-gram 寻址、表参数更新方式或共享全部投影。

harness 可提供 `memory.write/read/update/delete` 与 `history.search/open` 等工具。模型可以把明确希望保留的信息写入 E，在隐空间记忆模糊时调用历史工具寻找证据。工具返回内容作为新的可见输入进入当前状态；记录来源，避免把检索副本误记成刚发生的外部事件。删除 E 中的记录有明确操作对象；如需同时删除历史或相关 M 记录，应另有对应操作及作用域。

训练数据需要包含主动保存、修改、删除、检索和检索不到时的轨迹。分别评测允许工具时的系统能力和禁用工具时的 M 能力，避免工具查询掩盖隐空间读写失败。

## 4. M 的写入与读取

### 写入

每处理完一段已发生的经历，Writer 用可学习查询对因果隐状态进行压缩，产出多个 latent slot：

```text
Z_j = Writer(H_j, available_context)     # [n_slots, d_memory]
K_j = AddressEncoder(H_j, Z_j)           # 一个或多个可检索键
M.append(Z_j, K_j, time_range, source, links, codec_version)
```

首轮可比较每 256 token 写 4 / 8 / 16 个 slot，维度 256；这只是消融范围。8 个 fp16 slot 的内容载荷为 4096 bytes，约 16 bytes/原 token，另加地址、索引和元数据。这一倍率能保留多少内容必须通过训练验证。

多个 slot 允许不同细节分别占位；直接均值池化与单个段末向量作为对照。首轮固定周期必写，验证读写能力后再引入事件边界、显著性和容量控制，避免早期写入门把有用训练信号全部关掉。

写入时标记外部观测、模型自身生成、内部推断与检索副本的来源。读出的旧记忆不会自动以新观测身份重复写入；这可以减少错误被循环强化。

### 读取

查询由当前已处理前缀的隐状态与 S 产生：

```text
q_t = QueryEncoder(h_t, S_t)
ids = Retrieve(q_t, memory_index, time_constraints, budget)
r_t = MemoryReader(h_t, M[ids], metadata)
h'_t = h_t + gate_t * r_t
```

Reader 用记忆专用投影做 cross-attention，让后续生成层直接使用 latent。索引键解决“能找到”，内容 slot 解决“找到后能用”，两个目标分别训练。

仅靠最后几个 token 的 n-gram 难以处理改写、指代和跨语言查询。语义地址应作为主通道；实体或词法锚点、时间范围作为辅助通道。每次只读少量记录，放在任务活动缓存中，之后可在预算内再取关联记录支持多跳。

读取只能根据当前位置已经可见的前缀发生。段末产生的记录对本段较早 token 不可见，不能用整段末尾的 query 为整段开头选记忆。

## 5. 持续延长历史与远期模糊

经历离开精确窗口后依次进入多分辨率档案：

```text
近期段的多个 slots
    -> 多段的事件组摘要
    -> 更长时段的摘要
    -> 高层历史组织
```

Consolidator 训练如何保留人物、关系、变化、时间与尚未解决的问题，合并多个子记录成为父摘要。它必须接受递归压缩训练；一次压缩有效并不保证反复合并仍有效。

重要或常被使用的经历可以长期保留细粒度记录，普通经历逐步减少 slots。年龄本身不应决定删除：记录的用途、独特性、是否被新版本取代也需要参与。旧事实更新宜记录时间和版本关系，保留历史查询所需的前版本。

采用有预算的隐空间档案：容量或精度预算达到阈值后合并、量化或删除细粒度记录，允许细节不可逆遗失。模型主动保存到 E 的内容按显式记忆策略管理；必要时通过 H 的工具接口查找历史证据。H 的容量与增长成本由 harness 独立承担，不能把它忽略后声称整个系统存储恒定。

研发中的对照组可以临时保留未压缩记录，用于区分压缩损失、检索漏检和 Reader 失败；这不改变正式设计允许遗忘的取舍。

索引可组合时间树、语义分组和锚点映射。不能每次扫描所有历史键。固定候选预算的层级检索是近似搜索，必须测量漏检；树形结构不保证任意语义查询都能找到目标。索引根与热节点常驻内存，冷节点和记录落盘，避免把全量索引常驻 RAM。

活跃 RAM 由 W、S、活动记录数和热索引预算决定；档案保留时磁盘容量随历史增长，层级访问深度通常随记录数增长。严格固定检索步数需要接受额外漏检，不能同时声称所有历史精确可读与全部成本恒定。

位置编码用于有界的最近窗口；全局逻辑时间和物理间隔保存在元数据中。远期记录用可学习的相对时间特征，不把远期都放到不断增大的同一条 RoPE 轴，也不假设旋转天然产生单调遗忘。

## 6. 训练读写能力

训练样本应实际包含“经历 -> 写入 -> 超出近期窗口 -> 未来查询”。重要的回忆内容随机生成，并在测试中换实体、数值、语序、延迟和背景，减少依赖参数背题。

三个先后步骤：

1. **验证内容与读取**：先给正确记录加干扰记录，训练 Writer、Reader 与生成目标。训练图保留 `未来回答 loss -> Reader -> Z_j -> Writer`；记录写出后立刻 detach 会截断这一信号。
2. **验证寻址**：加入正确与错误地址的对比学习、相近实体、改写、指代和时间查询，再接实际近似索引。分别报告索引召回率与给定正确记录后的回答准确率。
3. **验证压缩与长寿命**：加入反复合并、量化、随机占用率、陈旧记录和长干扰流。比较完整记录与压缩记录对未来回答分布、事实准确率和时间推理的影响。

完整训练保留流式语言建模目标，用联合损失训练，避免只优化检索几何而损害生成。先验证小模块可以通过有限 unroll 学到读写，再测试从预训练阶段共同塑造主干表示。

不对整段生命历史反向传播：S 用截断反传；长延迟记忆用“源经历—未来问题”成对采样，并用当前 Writer 重编码被抽到的源段，保留源段到当前查询的局部计算图。训练时构造丰富的历史状态与背景记忆，运行时无需保留激活图或旧原文才能继续读取已有 latent。

主干参数冻结时仍需让梯度通过 Reader 和后续冻结层回到 Writer；冻结参数与在整个路径使用 `no_grad` 有不同语义。

## 7. 证明两个功能确实实现

| 测试 | 要回答的问题 |
|---|---|
| 整段 / 分块 / 逐 token 的数值对照 | 状态接口是否真正连续、严格因果 |
| 保存恢复 vs 持续运行 | 中断是否改变工作状态或记忆 |
| 窗口滑出后的任务与指代延续 | S 与 M 能否接续当前思路 |
| 单独保留 M，清空 C、S 再提问 | 内容是否真的被写入 M，而不是从工作状态绕过 |
| M 禁读 / 禁写 / 内容置乱 | 系统是否实际使用该路径 |
| 给正确记录 vs 实际检索 | 瓶颈在内容编码、读取还是寻址 |
| 多次更新与历史时点查询 | 当前事实、旧事实和矛盾能否区分 |
| 不同压缩深度与长期干扰 | 模糊是否可控，是否发生突发崩塌 |
| 训练长度之外的长流滚动 | RAM、延迟、记录增长、任务能力是否符合设计 |

专门的 M 诊断支路清空 C、S，是为了分离贡献；正常持续运行保留它们。测试场景包含单次事件、长任务、实体关系、多跳、改写问法、语义细节与需要逐字保存的内容，后者可能需要选择性保留更多 slots 或独立精确载荷。

## 8. 首轮实现范围

先落地状态 API、已有语言底座的状态接续、固定周期多-slot Writer、可读取的 M、harness 工具接口和 snapshot/restore。小记忆池阶段先用精确检索诊断能力；通过后训练全注意力窗口限制与记忆的联合适配，升级近似索引，加入 Consolidator 与遗忘。已有 GDN 混合模型的全注意力层需要单独适配，原生支持长窗口不等于 KV 和计算成本有界。

首轮成功判据是：发生一次新经历，滑出窗口并经历干扰后，模型能换一种问法使用它；同时工作状态继续演化，分块和中断恢复不改变语义。更大模型、Engram-W 扩容、主干在线梯度更新、复杂快权重记忆可在这个闭环成立后独立比较。

已有研究分别支持循环状态、记忆读写、压缩或检索中的部分机制，旧项目也有局部证据；它们尚未证明这里的完整组合可以稳定运行到任意长度。这个提案的各个环节仍需受控实验。
