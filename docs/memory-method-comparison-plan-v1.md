## 2. 要回答的三个问题

1. 同一冻结0.8B底座下，slots和生成的LoRA，谁更能把一次经历保存为可供多个问题使用的内容？
2. 多条经历一起使用时，错误主要来自写入损失、问题绑定还是载荷组合干扰？
3. 在5080上，收益是否值得其写入延迟、训练成本、每条记忆字节与额外显存？

首轮是资源受限的结构可行性对照。原论文训练规模、基座和实现不同，不能将这里的小型改造称为原论文复现，也不能由少量token的失败否定整条论文路线。

## 3. 三条结构分支与两个历史参考

| 分支 | 写入与读取 | 主要检验 |
|---|---|---|
| C：slots冷启动对照 | 现有Writer/Reader架构，新增模块从其初始化方案重新训练 | 相同新增训练量下的原路线基准 |
| D：D2L式小型生成器 | 冻结底座的源文本多层激活→Perceiver式压缩→逐层LoRA因子；学生只看问题 | 权重载荷与激活压缩的可行性 |
| S：SHINE式小型生成器 | 源文本＋共享写入适配器/可学习memory queries→逐层memory states→M2P→同规格LoRA因子 | 训练写入表征能否改善身份与内容绑定 |

三条分支共用原始Qwen3.5-0.8B语言权重，新增模块均从头训练、全新优化器/RNG/游标。C不继承4554的学习成果；4554、v7只作为独立历史参考，不能把它们与新生成器称为等训练量比较。

D/S优先使用相同生成目标：6个选定层的MLP down_proj、内容rank4，候选层为[3,7,11,15,19,23]，以实际模型配置核验后锁定。源特征和输出头尽量共享，新增可训练参数目标≤20M；层间输出头共享并使用层身份条件，避免直接生成巨大稠密矩阵。最终参数量、载荷字节和显存由实现预检给出。

这是两个论文的受限变体；SHINE原版更广的投影范围、D2L全层配置不在首轮混入。D/S共享输出rank、投影范围、缩放和存储dtype。slots与LoRA每条字节不能自然相等，报告准确率—载荷字节—计算成本，不由原始分数声称纯载体优劣。注入层与查询执行位置也作为方法差异公开。

动态LoRA使用生成器输出的带图A/B张量做函数式计算，不能通过Parameter.data复制或detach切断写入梯度；已有静态LoRA模块不能直接当作生成器实现。实例活动载荷按life隔离，生成/卸载/恢复身份显式记录。SHINE式memory queries优先用内部可学习向量，不扩tokenizer词表，其实际编码计算计入账本。

教师始终为同一冻结底座；写入阶段关闭已有记忆和生成的adapter，S仅启用其明确训练的共享写入适配器。未来问题/答案不进入写入器。教师的adapter关闭，学生问题不带原文。优先共享底座权重顺序计算，避免常驻第二份模型。

## 4. 先检查LoRA能否容纳任务，再训练通用写入器

审核后的准备阶段先做小型诊断：

- 测底座看到正确原文、全部原文、无原文的上界；只使用教师能正确解答的主任务，并保留失败率。
- 在不超过16个训练上下文上，用逐上下文SGD拟合LoRA作为诊断参照，检验相同rank/层选择是否能支持单事实及双事实。它不属于快速写入产品路线，也不能用其计时代表一次前向生成。
- 对新生成器做小型已见训练fixture，先验证梯度经过学生和动态LoRA传回写入器，再验证自由生成。目标为至少32个已见问题中90%正确；达不到先排查容量/初始化/梯度，停止放大试验，结果记为该受限配置尚未建立可学习性。
- 核验adapter禁用回到底座、活动载荷相互隔离、无跨样本泄漏、错误/空载荷对照、非空累计梯度完整中断恢复。

已见fixture只验工程可学习性，不作泛化或M5验收。诊断token和GPU时间独立记账，不混入正式进度。

## 5. 统一训练单元与数据

明确区分三个难度，避免把“一个adapter含两条事实”和“两份adapter组合”混成同一个成绩：

| 子阶段 | 原经历→载荷 | 同一载荷下的问题 |
|---|---|---|
| U | 单事实→一份载荷 | 改写问题，检验基本内容传输 |
| P | 双事实同一源块→一份载荷 | 分别问两个实体/属性，检验写入压缩与绑定 |
| C | 两个独立源块→两份载荷，两份均激活 | 分别问两条事实，检验组合干扰 |

slots按源块写记录，LoRA按源块生成adapter。C阶段对每个问题保持同一活动集合，禁止support标签替学生挑选或排序。两份LoRA使用独立增量精确相加：B1A1+B2A2，可沿rank拼接实现；不分别相加A/B制造交叉项，有效rank增长和成本如实报告。

三种结构使用同一版本化数据清单、按顺序相同的episode ID与题目、相同优化器更新次数和episode累积数。预先按最耗token的结构选择满足各支上限的共同episode前缀；实际学生token因额外编码/memory tokens不同可以不同，分别报告，不同时声称“样本完全相同”和“实际token严格相等”。首轮每支训练上限300k，U/P/C各预留约100k容量，40%保持比例沿用，具体前缀在消耗前锁定。

保留随机码精确传输，并加入教师可靠的自然语言属性/关系问题，输出长度和难度分层。源记录顺序、实体编号、字段位置、时间与答案独立变化；训练与开发使用独立世界/实体值及问题表述。更新、无证据和跨记录推理首轮以挑战集记录，核心读取通过后再加入正式课程。native保持语料保持评测专用。

## 6. 结构与目标分开比较

首轮三支统一使用：回答CE＋内容反事实损失＋既有语言保持目标，保持权重/采样规则相同；不默认叠加v7证据KL，也不把SHINE重建热身单独加给S。这轮回答结构在同一训练协议下是否可行，不作完整论文训练方法排名。

后续仅对有学习证据的候选做单因素对照，需下一轮审核：

1. D2L启发：相同结构/数据/初态，KL=0与经正确教师筛查的KL，比较其新增效果。
2. SHINE启发：相同结构/数据，重建/补全热身＋QA与等总预算QA训练比较；热身token全计入，不免费预训练。
3. 两个结果成立后再考虑结合。选择性地引入教师缓存/批量生成另记性能版本与实际预计算成本，不同时更换损失、课程、优化器和执行后端。

教师正确筛查可离线共享，缓存锁定底座、源文本、问题、tokenizer、目标定义、数值执行身份与实现SHA；只存需要的稀疏分布。首次生成成本单列，命中缓存不宣称端到端零成本。

## 7. 验收与停止规则

所有结构均使用自由生成、清空KV/GDN/conv的M-only测试；教师强制NLL、训练loss和attention质量只作诊断。

- 开发：保留原v6单/双候选各96题；新P/C分别16世界×3语言×2反事实版本×2问题＝192题，报告两问均对、两版本均对及实体/属性分项。
- 控制：关闭/替换载荷、问题互换、源布局/时间变化、无关记忆；检查固定候选集合，单独报告实际寻址，避免混淆oracle补入前覆盖率。
- 保持：原48篇native、原meanΔ≤0.05、95%上界≤0.10、单篇最大≤0.25。阈值不改。
- 中途：约100k/200k做固定48题开发快检；末尾做完整开发/保持。不开启test选模型。
- 基本读取门槛：独立开发单事实EM≥80%、关闭记忆下降≥50pp，并保持过线。P/C也须完整EM≥80%且显示问题/反事实绑定，才能扩到4/8载荷。阶段得分不单独代表M5通过，实际coverage@8等原要求仍保留。
- 若两个连续检查点读取与保持同时恶化，安全停止该支。若预算内不能建立基本可学习性，记录失败配置及预算，不继续加模型/加rank直到分数改善。
- 首轮只能筛查，不能凭小分差选胜者。候选通过后补独立种子、容量匹配及每GPU小时效用，测试集最后一次性使用；这些属于下一轮预算。

A链目前16,658,338/30M，正式余额13,341,662。首轮正式额度不是立即扣除900k，按三支实际消费增加；若用满则A累计17,558,338、余12,441,662。B20M不动。诊断上限不是额外声称正式训练进度；本轮全部学生计算上限1.05M及教师/编码器成本一起披露。后续扩大训练或修改总预算另行审核。

GPU任务仍经checked入口串行启动，不干预外部任务。使用完整已提交代码快照，原训练环境不覆盖；依赖需改变则在E盘另建环境并锁身份。首轮不下载完整8B或其他大底座，公开模型外部推理参照可单独申请/评估，不替代同底座对照。

每100微批及任何外部pause保存完整状态；生成器较大时先实测payload容量再提交。保存底座身份、全部新参数、Adam/AMP/调度器/累计梯度、四类RNG、数据游标及账本；动态载荷另保存内容/指纹、来源、活动集合和组合策略。非空累计边界暂停后在新进程恢复，必须与连续参考全payload一致；不以观察超时触发重启。达到磁盘、时间或显存约束则安全退出，若要改结构/后端必须新配置并重验。

## 9. 连续状态放到下一道门

首轮只验证M-only内容和组合。通过后才定义LoRA激活与持续C/S的联合语义：活动集合在已消费逻辑事件边界改变，记录版本和位置；分别检查逐token、外部分块、卸载/重载、删除/恢复。旧KV/GDN由旧权重轨迹产生，换adapter后继续使用不等价于新权重重放历史；不把重算近期窗口当作自动重建全部GDN。

暂不同时加入检索器训练、长期压缩、自动遗忘和全局底座训练，避免内容载体效果与状态工程混杂。

## 10. 审核后的交付与再次决策

审核通过首轮后：先实现统一载荷/评测接口与D/S最小生成器，完成准备门槛和资源测量；再按锁定共同前缀串行运行C/D/S，所有分支完整中断恢复、预算和成本可复查。交付同数据能力矩阵、原任务回归、native保持、写入/装载/首token/完整回答延迟、每条载荷字节、可训练参数、GPU小时和完整状态索引。

若全部失败，交付明确的可学习性与资源边界，回到写入信息/底座上界，不自动耗尽A余额。若有候选通过，下一轮提交训练目标对照、重复种子与扩大容量的具体额度，再审核。
