2026-10-26。用户已选择先走SHINE，覆盖上一条“三路均待审核”的状态。本次只执行S路线；C/D不启动。现有4554及v7全态继续保留，语言底座仍为Qwen3.5-0.8B。

## 结构与论文对应

新模块为`src/dsrsi/model/shine.py`，版本`source-memory-queries-axial-m2p-down-v1`。这不是原论文检查点复现。保留其源文本→共享写入适配器/可学习memory queries→逐层memory states→双向轴向M2P→动态LoRA的路径；缩小了投影范围、rank、层数及M2P内部宽度。

- 生成目标：索引[3,7,11,15,19,23]的MLP down_proj，输入3584、输出1024，rank4、scale1，因子FP32。
- 共享写入适配器：相同6处down_proj的rank4，仅源编码启用；问答时关闭。
- memory queries：`ceil(r*(din+dout)/hidden)`＝18，放在已观察源文本之后。逐层状态总输出宽度足以覆盖A/B；没有把待生成的全部因子压到单一向量。
- M2P：两块先沿memory位置、再沿层做双向attention的轴向模块，内部宽256、显式eager矩阵attention，零dropout。保留1024维原始memory states的残差，输出头共享；不是逐层独立MLP。
- 每份载荷生成110592个FP32参数，442368字节（432KiB），另计元数据；明显大于旧slots载荷，不能当作等容量比较。
- A头小随机、B头零初始化，使初始adapter为零但后续有梯度。输出是带图普通张量，不复制到Parameter.data，不detach。各份B_i A_i独立求和，不产生因子交叉项。

源编码关闭所有生成载荷，仅开启共享写入适配器；学生只有问题及动态载荷，使用全新KV/GDN/conv。全查询前缀与回答都受生成LoRA影响，和旧Reader仅特定位置注入的执行范围不同，作为方法差异披露。原始底座参数冻结，现有slots参数不迁入。

## 诊断顺序及额度

先执行诊断，不直接扩展正式训练：

1. 同一组小型上下文的正确原文/关闭记忆教师上界。先检查精确token及EOS，错误教师不当作可靠上界。
2. 少量上下文逐个SGD拟合独立LoRA，作为容量诊断。它利用每个上下文的问题答案监督，不是通用快速写入器或无监督文本内化，不用其速度替代前向写入时延。
3. 从头训练共享生成器的小型U/P/C已见fixture，门槛为至少32个已见问题90%自由生成正确；它只证明工程可学习性，不是泛化/M5通过。U为一事实/一载荷、两个问法；P为两事实/一载荷；C为两独立事实/两载荷，所有问题都用相同活动集合。
4. CUDA完整状态及独立进程累计中断恢复对照；显存分配≤6GiB/预留≤7GiB、预检可用≥8GiB、E盘绝对余量≥20GiB。恢复门槛和学习门槛都通过后才能进入正式首批。

诊断学生总额≤150000，使用所有诊断进程共享的原子账本，训练、评测源编码和学生生成都计入。裸底座/原文教师输入另记教师成本。每次计算先保守预留，成功后按实际输入结算；异常留下的预留不自动退还。多次验证、重放和失败尝试均不能隐去。首轮正式至多300000学生token/3 GPU小时，仅在门槛通过后另建run，A链实际消费追加到16658338；B20M不动。

旧权重不继承，新生成器的诊断训练也不免费转入正式run：若正式采用诊断训练过的参数必须另记初始化及全部训练历史，否则正式从锁定原始初始化开始。此阶段不默认加入KL或重建热身，目标仍是QA CE＋内容反事实；保持项在正式课程按原40%与既定目标接入，已见fixture不是保持或长期能力验收。

## 断点与评测恢复

训练入口`python scripts/shine_pilot.py`，mode=oracle或generator，stage明确为SHINE_diagnostic，不写成旧A的resume。全态保存使用现有CheckpointStore，包含全部可训练参数、Adam、累计梯度、四类RNG、数据游标和计账；源/查询计算图在微批backward结束后释放。每20微批及外部pause/stop保存，未耗尽算法目标不能标completed。

保存身份包含底座文件摘要、tokenizer、完整源码摘要、脚本、结构、fixture、优化器配置及CUDA运行时，恢复不改lr/累积/账本/数据。执行窗口与评测频率可以不同，但不能改变已消费训练序列。活动载荷在每个scope finally中清理，checkpoint边界为空；本轮没有持续C/S语义。

评测逐题原子journal，绑定训练身份、微批与权重内容SHA；生成期间只用answer-free prompt。暂停在当前查询结束后保存journal，并保存训练状态，包括未完成累积；恢复不丢已消费微批。评测恢复可能重编码当前上下文，该额外计算照常计账，不能假装没有重复成本。

所有GPU调用经完整已提交代码快照中的run_5080_checked.py。模型、环境、状态、账本、日志和缓存均放E盘，不覆盖旧环境，不修改外部GPU任务。遇到观察超时先查实际进程和完整状态，不重复提交或重置。
