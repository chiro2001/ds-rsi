# 从头训练与已有模型改造：预算 v0

日期：2026-10-09。这里只做成本计算和路线建议，未启动训练，也未确认新的设备使用配额。

后续已选择 Qwen3.5-0.8B 为首个底座。具体记忆结构见 [接入提案](qwen35-08b-memory-architecture-v0.md)，训练吞吐仍待实现后的实测。

## 1. 推荐判断

目前更适合在已有、语言能力较完整的 GDN 混合模型上新增记忆结构，先训练读写模块，再联合适配持续上下文、压缩遗忘与工具行为。从头训练小模型仍适合有限机制消融；从头训练 2–4B 语言底座需要显著更多数据和机时。

“1 参数约 20 token”是从头训练稠密语言模型时的粗略算力最优配比。它不保证下游饱和或记忆能力，也不要求微调时重新消耗 20 倍底座参数量的 token。MoE、查表参数和不同注意力结构需要另算激活计算量。

## 2. 硬件与公式

沿用旧项目的预算口径：910C 单 die BF16 持续值 376 TFLOPS，8 die 合计 3.008 PFLOPS。这里 8 die 对应原设备的 4 张双 die 卡。

对稠密模型用近似：

```text
N = 模型参数数
D = 实际处理的训练 token 数
C ≈ 6 × N × D FLOPs
D = 20 × N 时，C ≈ 120 × N²
墙钟小时 ≈ C / (8 × 376e12 × 有效算力利用率 × 3600)
总 die·小时 = 墙钟小时 × 8
```

6ND 忽略或简化了注意力长度开销、重算、额外读写模块和索引处理。10%、20% 是未验证新实现的两种规划情景；旧实现曾因算子派发等问题只有约 1.5%–2%，不能假定新模块必然达到这些效率。

## 3. 从头训练，D=20N

| 稠密模型参数 | token 预算 | 20% 利用率，8 die 墙钟 | 10% 利用率，8 die 墙钟 |
|---|---|---|---|
| 0.2B | 4B | 2.2 小时 | 4.4 小时 |
| 0.5B | 10B | 13.9 小时 | 27.7 小时 |
| 0.8B | 16B | 35.5 小时，1.48 天 | 70.9 小时，2.96 天 |
| 1B | 20B | 55.4 小时，2.31 天 | 110.8 小时，4.62 天 |
| 2B | 40B | 221.6 小时，9.23 天 | 443.3 小时，18.47 天 |
| 4B | 80B | 886.5 小时，36.94 天 | 1773.0 小时，73.88 天 |

以上是计算量情景估算，尚未包含数据处理、教师生成、评测、存点、故障恢复、多臂消融和额外长上下文训练。

2B / 40B token 若只能达到 5%，需要约 36.9 天；若达到 2%，约 92.3 天。设计新记忆结构时，低利用率可能成为比峰值算力更大的成本因素。

旧 Mini 是约 188.8M 总参数、含表与 MoE 的特定实现。8 die 记录约 9.8 万 token/s、8.9B token 约 25 小时。保持这个吞吐，仅把预算换成 20×188.8M≈3.78B token，约 10.7 小时。这是旧实现实测吞吐的预算外推，与表中稠密模型情景不同；不能按同一 token/s 外推到 2B、4B。

来源：旧项目 `reports/070-910c-flops-and-budget.md`、`reports/074-training-launched-8chip.md`。当前约 8.9B 的已训练消费量不等于现有数据库存总量；本轮尚未统计全部 token 池及去重后独立数据量。

沿用权重的建议顺序：

1. 先保留底座已有语言和 GDN 能力，训练 Writer、Reader、Query/Address 与门控。底座冻结仍需允许 Reader 注入点之后的梯度传到记忆路径；冻结权重不保证加入模块后的输出行为不变。
2. 对记忆接入层及需要改变行为的层加 LoRA，混合语言保持任务、写后读任务和工具轨迹。实验通过后考虑小学习率解冻部分主干。
3. 对原有 full_attention 的可见历史逐步施加有界窗口，训练模型通过递归状态与 M 接续远期内容。单纯加 LoRA 不会自动消除全注意力 KV 的线性增长。
4. 训练多次压缩、陈旧信息更新、显式明文记忆操作和按需历史查找；分别评测有工具与无工具两种条件。

## 5. 微调成本口径

微调的新增 token 预算由任务覆盖与验证结果决定，不由底座参数数乘 20 决定。可先做 30M–100M 的读写和工具协议试验，信号成立后扩到 300M–1B；这些是实验预算，不是成功所需数据量的已知下限。

以 2B 全参训练的 6ND 计算量作参考，沿用 10%–20% 效率情景：

| 新增实际处理 token | 8 die 计算量参考墙钟 |
|---|---|
| 100M | 0.55–1.11 小时 |
| 300M | 1.66–3.32 小时 |
| 1B | 5.54–11.08 小时 |

这不是新记忆模型的实测时间承诺。源经历编码、查询与回答、语言保持数据都应计入 D；多次前向、递归展开、Reader 反传、压缩模块、近似索引及框架开销需单独计入。教师生成和评测另算，不能把长经历样本只按答案 token 估时。

LoRA 主要降低可训练权重、梯度和优化器状态占用，计算仍包含底座前向与相关反向。冻结底座时也可能需要输入梯度，因此不能把可训练参数量代入 6ND 估算整次训练，也不能承诺与参数减少比例相同的加速。

建议在拥有新配额后先测 50–100 个稳态训练步，记录源段与查询总 token、序列长度、反传跨度、显存、每步时间与多 die 扩展，再用实际吞吐替换上述情景估算。计时应包含记忆模块，区分编译预热与稳态。

## 6. 数据优先级

本项目应优先构造具有延迟依赖的经历流：一次出现的新事实、更新与旧版本、指代和改写、多跳、长任务、逐次压缩、明文写入/删除和历史检索。合成数据可以扩大随机实体和距离覆盖，真实长对话与任务轨迹用于减少模板依赖。

已有模型提供语言和世界知识基础，新增数据集中训练如何保留与使用经历。各模板、实体与历史长度需独立划分测试；原实验的单一检索目标损害生成的结果不构成联合记忆微调必然失败的证明，但提醒我们保留语言目标和生成回归。
