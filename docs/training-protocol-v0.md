## 1. 首轮需要证明的能力

发生一次未见过的经历，写入 M；原上下文不在当前输入中，全部短期状态清空后，模型仍能换一种问法使用这段记忆。随后再验证真实连续流中的工作状态接续、压缩遗忘和工具操作。

训练单元是一个 episode，包含已发生的源事件、背景/干扰、未来查询与监督。答案和证据标注仅作为标签，不进入 Writer、检索 query 或学生前缀。查询阶段也不得重新拼回源原文。

同一 episode 的多个查询共用源记忆，分别计分。首轮查询/答案阶段禁用 M 写入，避免 teacher-forcing 的正确答案被写入后帮助同 episode 的下一道题。运行时的自主生成写入在后续训练，记录为自身生成而非外部确认。

## 2. 两条样本执行路径

### M-only 读写与诊断

```text
源事件 -> 冻结底座前12层 -> Writer -> 带图的 Z 写入训练池
    -> 完成源记录提交
    -> 清空 KV、GDN、conv、pending Writer；保留 M 及其计算图
    -> 独立编码未来问题 -> Reader -> 底座后半段 -> 回答 CE
```

清空工作状态不能对 M 做 detach。源段 H11 在底座冻结时可在 no_grad 下生成，Writer 必须在该范围外执行；Reader 之后的冻结层仍需对输入求梯度。

首轮受控 A/B 样本默认 `source_encoding=independent_events`，每个源事件单独编码后写 M，用来让直接证据与负样本标注可检验。正常运行和阶段 C 使用 `continuous`，保留整个经历流的状态，不能将独立事件编码当作已经完成持续上下文。

连续编码时，后来的 H11 可能携带早先事实。因此删除原记录并不证明证据消失；缺证据样本必须清除所有潜在副本，或在明确独立编码的条件下构造。不能把所有非原始记录都标成负样本。

不足 256 token 的源片段可在显式、已观察到的源段结束事件提交，只池化有效 token。任意物理 batch/chunk 的结束不会自动产生这个事件。正式长样本继续按 256 token 提交，标签映射到实际记录跨度。

### 连续状态路径

```text
源经历 -> 任务/背景/干扰 -> 后续经历 -> 继续任务或提问
             C、GDN、conv、M 持续传递
```

训练时在指定边界截断反传，但保留状态数值。不能把 reset 与 detach 混为一谈。完整状态与 M 各自承担信息，禁用 M 不要求所有连续任务都失败；独立 M-only 分支用于归因。

源段、查询和背景都计入学生实际处理 token；教师计算另记。查询的多次重新编码、源记忆重新编码与重复 epoch 都计入实际消费，不能只统计监督答案长度。

## 3. 样本族

| 族 | 源经历与未来任务 | 首轮路径 | 主要监督 |
|---|---|---|---|
| 单次新事实 | 一次出现的随机实体/值，未来回忆 | M-only | 回答 CE；同问题不同值的反事实对照 |
| 改写与指代 | “设备暂放东侧柜” -> “上次它收在哪里” | M-only | 回答 CE、地址排序 |
| 经历与理由 | 做过哪些尝试、结果、失败原因和决策 | M-only | 语义回答 CE，事实槽位和理由分别评测 |
| 任务接续 | 跨多段的任务步骤、完成项、下一步 | 连续流 | 助手动作/回答 CE，状态接续对照 |
| 更新与时间 | 旧值、新值、当前问题与历史时点问题 | 两条路径 | 回答 CE、时点对应证据排序 |
| 多记录证据 | 多条过去事件共同支持答案 | 先 oracle 候选 | 多支撑组覆盖损失、回答 CE |
| 压缩与遗忘 | 多次合并后使用应保留的信息 | M-only + 连续流 | 压缩后回答 CE，正确教师分布蒸馏 |
| 无证据或不相关记忆 | 没写入、已移除证据或检索漏掉 | M-only | 表达信息不足；工具阶段可选择历史查询 |
| 明文记忆操作 | 主动保存、读出、更新、删除指定记录 | 工具轨迹 | 工具调用与回答 CE，执行后存储状态 |
| 历史查找 | M 模糊或无充分证据，search/open 后使用原文 | 工具轨迹 | 调用参数、结果后的回答 CE |
| 语言保持 | 普通语言/指令任务 + 不相关 M | 两条路径 | 普通 CE + 底座分布保持 |

首轮控制任务用程序生成真值，实体与答案随 episode 随机化；同时加入经历理由、任务与关系，防止全部样本退化成编号抄写。中文起步占 60%、英文 30%、跨语言查询 10%，这是采样起点，实际 token 配比另记。

## 4. 三个具体样本

### 一次经历与改写

源：`青杉仓本次入库校验码为 Q7-492。`

提交 M，清空短期状态。未来问题：`上回青杉仓入库时用的是哪个码？`，标签：`Q7-492`。

同一问题的配对样本只将源值换为 `R2-815`，标签同步改变。正确行为随本次经历变化；只背实体、模板或参数中的固定答案不能同时答对配对样本。

### 时间更新

09:00：`采样设备暂存在东侧柜。` 16:00：`设备搬到了西侧架。`

两个查询均发生在 18:00：`现在在哪？` -> 西侧架；`今天10点时在哪？` -> 东侧柜。

旧记录在第二个查询中是正确证据，不能因为它较旧就标成负样本。源时间、查询时间与目标时点分开记录；目标标注不会作为隐藏答案提示输入模型。

### 工具查历史

源经历曾发生，但其 latent 证据已不可用。问题仍询问校验码。

轨迹：`history.search(实体和事件关键词)` -> 返回过去记录的 id 和不含答案的摘要 -> `history.open(id)` -> 返回真实记录 -> 助手回答。

search 参数只能包含当前已知线索，不能携带尚未查出的正确校验码。工具返回是环境观察，其 token 不作为助手的监督目标。

## 5. 回答与动作的主损失

对每个查询/助手动作，只监督该事件的目标 token，含结束标记：

```text
L_answer_i = sum_t(mask_i,t * CE(logits_i,t-1, token_i,t)) / sum_t(mask_i,t)
L_answer = mean_i(L_answer_i)
```

问题、源观察、干扰、工具返回与 padding 在 response-only 样本里没有回答损失。标签对齐采用右移预测，回答首 token 与结束标记必须都被监督；结束标记之后的换行/下一条消息不属于该回答。

编译结果显式携带 `retrieval_query_index=prompt_length-1` 与 `memory_read_from`。teacher-forcing 的最后一个状态已经含有答案，不能用于检索；依据完整问题取回的新候选也不能反向注入更早的问题位置。Reader 的位置 mask 仅从检索当时的可见位置开始激活。

按查询/事件先归一化，再在相同任务族中取平均，避免长答案与多查询 episode 无意占据全部权重。分布式训练需按全局有效查询数归一化，不能让 padding 多的 rank 获得相同的假分母。

控制事实使用简短输出，同时有解释与接续任务输出。自由生成评测使用未见答案前缀，不能把 teacher-forcing 的 token 命中率当作实际回忆准确率。

## 6. 寻址损失：与记忆内容学习分开

Top-k 是离散选择，回答 CE 不会自动训练 query/key 的选址。索引器需要显式支撑监督。

每条记忆有两个归一化 key，使用 log-mean-exp 聚合，而不是把两条地址直接求均值：

```text
s(q,r) = log(mean_j(exp(cos(q,k_r,j) / tau)))
tau 初始取 0.07
```

一个问题可能需要多个支撑组 G，每组 P_g 可包含等价记录，N_g 只包含真正不支持该问题的记录：

```text
L_route = mean_g(-log(sum_{r in P_g} exp(s(q,r)) /
                       sum_{r in P_g union N_g} exp(s(q,r))))
```

其他合法支撑组不能作为负样本。多跳问题不能把所有正确记录并为一个正集合后只奖励找回其中任意一条；评测要报告所有必要组是否取齐。

初期 query 输入 H11 和 key 输入 Z 都 stop-gradient：L_route 更新地址投影和 key pooling，不改写 Writer 的内容编码或主干的生成表征。L_answer 继续训练 Writer 与 Reader。只有在有证据表明有益时，再实验低权重的联合表征学习。

负样本包括同实体不同属性、相似实体、同属性不同值、当前问法下过期的值、同时间不同事件与普通无关记录。候选存在等价证据时全部标注，避免 false negative。

训练从“正确证据保证进入候选”逐步过渡到实际检索，记录 oracle 注入比例；验证和最终测试从不注入正确答案记录。实际检索缺证据时，不继续强迫无证据的 Reader 输出随机真值：训练表达信息不足或工具回退，L_route 仍监督应找到的记录。端到端事实准确率会把这次回退计为未完成回忆，不能用拒答通过准确率门槛。

## 7. 语言保持损失

L_keep 使用真实普通语言/指令任务，输入不相关 M，要求既能完成任务又能抑制错误记忆。它由普通 CE 和底座教师分布保持组成。

教师是原底座，不含新增记忆；仅在不需要记忆、且当前窗口足以完成的任务上做保持。不能把无记忆教师对新事实的无知蒸给需要 M 的样本，也不要求有损远期记忆复制无界原文条件下的全部预测。

大词表可在抽样位置做 top-32 + tail 概率质量 KL：

```text
L_KL = sum_{v in teacher_top32}(p_v * log(p_v/q_v))
       + p_tail * log(p_tail/q_tail)
```

两侧 tail 都是完整归一化分布的剩余质量，不是把 top-32 单独归一化后冒充完整 KL。

底座冻结且 M 为空时，学生与教师相同，保持损失对新模块没有学习作用；因此阶段 A/B 保持样本要带不相关 M。对这些样本的 Z 可 stop-gradient，主要训练 Reader/门控拒绝无关内容，避免保持目标把 Writer 推成全零。加入 LoRA 后，还加入 M 为空的普通任务保持。

## 8. 压缩与遗忘损失

先固定已经验证的 Writer/Reader，训练 Consolidator 把叶记录合成摘要。未来查询仅通过摘要回答，叶记录不能仍藏在候选池、短期状态或 history 工具返回里。

```text
Z_summary = Consolidator(Z_children)
L_compress = CE(answer | query, Z_summary)
             + 0.2 * KL(teacher_leaf_memory || student_summary_memory)
```

教师使用未压缩叶记忆，且通过自由生成或程序可检验答案筛查、确认对该题能够答对时才使用蒸馏项；不能仅凭 teacher-forcing loss 判断教师正确。程序真值 CE 是主要目标。教师、学生使用相同问题前缀、独立缓存状态，教师分布 stop-gradient。Consolidator 不读取未来 query 或答案来决定怎么压缩，未来损失可以作为训练监督。

摘要也需要产生可检索的 key，并在摘要候选上训练地址覆盖；仅在 oracle 摘要条件下能答对还不够。地址模块更新时混合叶记录和摘要，检查旧 codec/叶记录的兼容性。

随后加入 1/2/4/8 层递归合并与预算压力，分别测事实、关系、任务目标和时间信息的保留率。存储预算先作为固定 slots/record/bytes 约束，不依靠早期门控稀疏惩罚来实现，否则模型可能学会完全不读不写。

压缩倍率不证明某个具体细节已经丢失。缺证据训练采用确实没有充分证据的构造；不能仅因为压缩过就把仍可能编码在摘要中的答案标成“不知道”。隐空间能力与工具回退能力分别计分。

## 9. 工具损失与主动记忆行为

使用原 Qwen 工具协议，监督助手的工具名称、参数序列、结束标记与最终回答。样例中的 `tool_calls.function.arguments` 是结构化数据；实际模板会渲染为 `<tool_call>`、`<function=工具名>`、`<parameter=参数名>` 标签序列，监督渲染后的 token，评测再解析为结构化参数比较。环境负责执行确定性的测试工具并产生结果，模型不需要预测工具结果 token。工具返回对象先序列化为确定性 JSON 字符串供模板渲染，不直接使用 Python 字典的显示形式。

工具样本应覆盖明确保存请求、为尚未完成任务主动保存、修改已有记录、删除指定明文记录、读取明文、历史查找和不需要调用工具的对照。memory.delete 的监督明确作用于 E，不训练模型声称它同时抹除了全部 M、历史或参数知识。

M 为空且底座全冻结时，纯工具 SFT 没有可训练路径。因此工具行为训练放在启用局部 LoRA/可训练主干适配的阶段 C；阶段 A/B 的 harness 可以执行工具，但不把恒定工具 CE 当作已经训练了该能力。

L_tool 与 L_answer 使用相同的 response-only CE 实现，标签集合分开统计。后续可通过多步执行结果评估工具行为，首轮不需要 RL 或测试时修改主干参数。

## 10. 首轮课程与损失权重

首轮学生输入预算 **50M token**：A 30M，B 20M。这是验证预算，不是成功所需数据量的保证。

| 阶段 | 更新参数 | 主要目标与初始权重 |
|---|---|---|
| A：读写，30M | Writer、Reader、门控、时间/来源编码 | 回答 CE 1.0；L_keep 0.2；oracle 候选；暂不更新地址和压缩器 |
| B：寻址，20M | A 的参数 + Query/Address | 回答 CE 1.0；L_route 0.05；L_keep 0.2；逐步混入实际检索 |
| C：持续状态与工具 | 记忆参数 + 选定层 LoRA | 任务/工具/流式 CE 1.0；route 0.05；keep 0.2；窗口由较长上下文适配至 2048 |
| D：压缩遗忘 | 先 Consolidator，再按验证需要联合更新 | 压缩后回答 CE 1.0；正确教师 KL 0.2；keep 0.2；route 按需要 |

A 起步 75% 记忆 episode、25% 语言保持单元；记忆内部为新事实 40%、改写指代 25%、经历/任务描述 20%、更新 10%、缺证据 5%。B 起步 70% 记忆、30% 保持，在记忆样本上同时计算地址损失。比例按采样单元，实际输入和监督 token 比例另记。

先小池 16/64 条记录验证 Reader，再扩到 256/1024 条验证选址。长延迟训练用源段—未来问题成对采样，距离与时间为元数据，不能声称跳过背景后已经训练了抵抗同量级真实干扰；阶段 C 再真正滚动处理 2K/8K/32K 及更长干扰流。

所有权重建立在各项独立归一化之后，先监控共享参数的梯度范数与实际更新。L_route 梯度按设计不进入 Writer/主干；如辅助项压过回答学习，应根据开发集调整，不把数值较小的 loss 当作梯度影响较小的证据。

## 11. 多跳所需的小结构扩展

首版两个 Reader 共享 top-8 候选，适用于一次检索可以取齐的证据。真正的跨记录多跳可能需要读完第一条才知道第二条的地址。

这类样本先做 oracle 候选下的推理诊断，标注 `requires_query_update=true`。后续可加一个小 QueryUpdate：从 Reader A 之后当前位置的表示产生第二次查询，Reader B 读取合并候选，预算仍有上限。Writer 仍使用读取前的 H11。不能把靠强塞两条正确记录成功的结果称为已经实现多跳检索。

## 12. 划分与计分纪律

- 按 episode/world/反事实配对组整体划分 train/dev/test，多个查询和变体不得跨集合。
- 测试包含未见实体、随机值、问题模板、语言组合、证据位置、干扰类型与压缩深度。
- 生成器版本、随机种子、tokenizer 指纹、工具 schema、实际记录映射和消费顺序都进入 manifest。
- Gold answer、support groups、oracle 注入和目标时点标注均为标签，只将明确的可见时间表达提供给模型。
- 相邻 episode 的 GDN、conv、KV、M、明文工具状态互相隔离；同 episode 的连续路径保持状态。
- 评测使用自由生成；oracle 阅读、实际检索、M-only、连续运行、有工具/无工具分别报告。
- 随机事实回答同时报告准确率、无证据猜测率、反事实配对一致性、检索组覆盖率、语言回归、存储与延迟。
- 教师正确答案、真实背景全文和工具结果不能在测试答案前作为隐含输入泄漏；测试期间不做 teacher-forcing 写入。

首批机制目标建议：控制事实的 oracle M-only EM 达到 80%，关闭/置乱 M 后至少下降 50 个百分点；实际检索的必要证据组 coverage@8 达到 90%；普通短任务 NLL 相对底座增幅不超过 5%，并检查自由生成。它们是首轮受控验证门槛，不代表真实长期智能达标。

## 13. Tokenizer 与 mask 核验

本轮使用远端已有 Qwen3.5-0.8B tokenizer 做 CPU 模板检查，未加载模型或占用 NPU。实际结束 token 是 `<|im_end|>`，id=248046；padding id=248044。11 个语义 episode 中的 19 个回答/助手动作都通过了前缀可加性、目标结束位置检查；每个完成段在结束标记后还有 1 个模板换行 token，应屏蔽。结果与 tokenizer 配置指纹保存于 [模板核验 JSON](../data/examples/tokenizer_template_checks.json)。

统一先渲染聊天模板，再获取精确 token 边界。不能把 Python 字符长度当成 token 长度。本模板没有 generation 标签，不能依赖自动 assistant mask；某些版本的 `apply_chat_template` 返回 BatchEncoding。本轮核验使用逐助手事件的 prefix-target 渲染；后续如果把多事件打包成整段监督，还需验证最终完整模板中的各事件边界保持一致。

编译器必须断言：回答首 token 有 label、结束 token 有 label、prompt/工具观察/padding 为 -100；目标右移正确；无记忆输入与源段隔离；记录只由已完成有效前缀生成。连续状态还需检查 padding 不会让 GDN 的最终有效状态被额外衰减，不能仅把 padding hidden 置零就假定状态不变。

示例 JSONL 是 11 个语义预览 episode，短背景只演示顺序；生成器另提供可扩展的随机控制 episode。支撑跨度到运行记录映射、课程消费执行器、实际模型训练与真正长干扰流仍待完成。生成数据和编译缓存存放在 `artifacts/`，manifest 的池 token 统计不等同于实际训练消费。
