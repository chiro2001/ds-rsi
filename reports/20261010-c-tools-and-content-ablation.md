日期：2026-10-10。远期目标保持 active。正式训练、持续上下文课程、压缩语义训练及完整能力验收仍未完成。

本轮实现 Writer 后 12 层的 FP32 LoRA、真实 harness 工具轨迹生成、单助手事件 CE、M-only 回放、原底座语言保持，以及独立的生成/工具执行评测。运行入口和损失见 [C 工具阶段](../docs/stage-c-tools.md)。

**121 项 CPU 测试通过**，覆盖 M 为空时的真实 LoRA 梯度、零初始化一致性与 H11 稳定、单/双 rank 完整恢复、暂停前 journal 建立、冻结增量参数恢复、同形状不同结构拒绝、标签不影响生成、模型生成参数驱动实际操作，以及未完成/不合法动作不执行。

## 实际 0.8B 双 rank

[恢复原始数据](pretrained-cpu-tools-recovery.json)：完整 BF16 底座、两个 CPU rank、rank8/alpha16 LoRA **1,302,528 参数**。连续执行 5 微批，与 rank1 第 3 微批暂停、重新加载后执行到第 5 微批比较，全部数值训练态与可见 journal 身份/revision 一致；目录路径按同角色 journal 归一化。

最终 1 optimizer step，累计梯度 1/4，全局 5887 学生输入 token；实际采样包含 history、update、read、write 与 temporal_update 回放。该短样本未抽中保持单元或普通确认回复，教师账本为 0，不能据此证明课程混合充分或语言保持。最后代码的完整对照约 55 秒；HCCL 未验证。

checkpoint 新增冻结增量模块和实际记忆结构信息，避免把 Address/Consolidator 随机初值当作原底座的一部分。C 精确恢复还验证执行文件和包版本身份。较早用于独立评测的 C snapshot 与最终恢复 run 的完整数值态已比较一致，身份扩充并未改变参数或优化器。

## 工具执行与原底座对照

[微调后诊断](pretrained-cpu-tools-free-eval.json) 与 [关闭 LoRA 的原底座对照](pretrained-cpu-tools-base-eval.json)：各 1 个 dev 世界的 write/no_tool 两例，每回合最多 64 个新 token，最多 4 回合，**使用显式并行预填充诊断**。

两者都正确完成明文保存和算术回答，请求操作成功率均为 100%；严格示范端到端匹配均为 50%，成功的是算术对照。写入场景的确认措辞与示范不同，微调后的模型还进行了额外验证读取。底座本身已经能调用这里的工具，**没有微调能力改善证据**。2 例和并行路径也不能作为正式工具门槛。

实际执行第一次暴露出工具返回仍为 Python dict、未转为原生模板接受的 JSON 字符串的问题；生成入口已统一正常化消息并重跑通过。工具返回没有被当成助手标签，评测没有用正确后续动作代替模型生成。

## M 内容消融

新增 `foreign`：选择保持 actual 地址，所有选中内容替换为另一反事实 life 的 slots，原记录不被修改；单元测试验证每条 payload 替换、地址保持与源 life 隔离。它区别于可能把支撑内容留在同一 top8 集合里的池内置乱。

[M 消融数据](pretrained-cpu-tools-m-ablation.json) 使用同一短训练数值状态，默认单 token 路径，1 个 dev 世界×2 反事实变体，5 模式，每题 **8 个新 token**。各模式原答案 EM、成对 EM 均为 0，foreign 跟随替换答案也为 0。实际地址覆盖为 100%，它不能证明读出内容有效。输出预算较短且模型尚未完成 A/B，不能从这份 smoke 推断最终语义能力或性能；没有通过回忆门槛。
