# A/B 数据版本强化与恢复

旧 A/B 合成数据中，支撑一直使用“青杉/Cedar”，干扰一直使用“海松/Pine”；支撑还固定在源序列末尾。固定模板与源类别也使单条位置事实容易通过记录类型被挑出，不能充分证明实体/属性条件下的记忆寻址。

新版本 `ab-v2-matched-entities` 由 `data/robust.py` 实现。所有同世界正负记录共享随机选择的实体前缀；近似名称的其他实体使用同一属性，同名实体使用不同属性。位置/决策负例与其任务的内容类型一致。支撑位置随机，记录 ID 为无语义随机字符串；更新任务保持旧事件先于新事件、壁钟时间单调及9点/16点真值锚点。

反事实两种变体保持问题、负例、ID、时间和位置一致，仅改变支撑事实及其程序真值。缺失证据任务两种变体都明确移除对应支撑，拒答目标不变化。train/dev/test 由各自 split 的独立确定性世界和问题模板构成。

400个中文事实世界的审计中，四种前缀均出现，支撑覆盖全部0–7位置；2,800条负例包含1,200条同名异属性和1,600条同前缀近似名称。真实 Qwen tokenizer 编译了432个跨任务/语言 episode，源记录最长51 token。见 [审计清单](robust-ab-data-v2-audit.json) 与 [语义样例](../data/examples/robust-ab-v2.jsonl)。

新 A/B checkpoint 同时保存数据 revision 和生成器、编译器、工具模板的 SHA256。恢复及独立评测不接受同版本名下变更了实施文件的数据。旧 `ab-v1` 生成器文件保持原样，恢复必须显式指定旧 revision 与 mixed 课程；配置身份沿用其原格式。本轮从原始 NPU checkpoint 的副本成功在第5微批继续到第6微批，并保留累计梯度；未修改旧报告所引用的 run。

完整0.8B 四 rank HCCL 对新数据再次完成第3微批暂停、恢复到第5微批的完整状态逐位一致验证，见 [原始结果](pretrained-npu-robust-data-recovery.json)。本地158项 CPU 测试通过，覆盖原控制、恢复、工具、持续状态，以及新数据/旧版恢复和消融模式共用前缀的生成一致性。

独立自由生成现在可在授权 NPU 上执行。各模式只共享问题在读取记忆前的相同数值缓存，标准单 token 执行不变，每个分支独立 fork。foreign 消融替换其他反事实 life 的全部选中 payload，保留原地址；标签/真值仍只在生成结束后用于评分。

这仍是机制控制数据，不能替代广泛语言保持或真实长期经历数据。新数据的恢复证明不构成能力证明。后续按固定30M学生输入预算推进 A，分批保存并做 oracle/off/foreign 自由生成；A 的读写能力通过后才进入 B 的实际寻址。M5–M7、压缩 D、正式训练与权重交付仍未完成。
