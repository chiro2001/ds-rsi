# Qwen3-0.6B SHINE受限方法复现

2026-10-26。本轮完成已批准的单5080小模型训练、完整恢复及冻结代次评测。**官方结构可以运行，能拟合部分已见事实并快速生成LoRA；通用新内容写入尚未通过。** 还观察到QA阶段后重建接口退化。不能将这些小样本数字视为论文成绩复现或项目M5通过。

## 实现与范围

官方提交`fd606798c5d0e0f7d2c82df1204a83f8a1104036`实际已经提供0.6B配置及脚本；此前“未找到小模型入口”的判断已修正。本轮直接保留其数值代码，只有包相对导入调整。沿用生成rank8、共享写入rank128、28层全部q/k/v/o/gate/up/down、4层轴向M2P、宽1024/8头/FFN2048、post-norm/GELU、rl展开和scale0.001。176个memory tokens直接展开为5046272个FP32因子，不加入旧试验的低维投影及A/B头。

冻结Qwen3-0.6B，训练114728960个新增参数；新经历的写入是源编码及M2P前向，不做逐文档SGD。学生读取只收到问题和动态LoRA，不收到源原文；各测试问题独立清空cache。源的身份元数据不输入网络，也不看未来问题选取载荷。

明确差异：torch2.10/cu130适配5080，独立Transformers4.57.1覆盖层；FP32/eager、禁用AMP/TF32/compile；单卡累积4，未保持原8卡的有效批量；未复现完整group packing、6B语料规模和原调度。单卡原脚本优化器分组会误纳冻结参数，本轮过滤并查重，按作者注释将memory tokens纳入更新，和原DDP排除规则有差异。短预算warmup为4步。完整来源、SHA与协议见[复现协议](../docs/shine-qwen3-reproduction-v1.md)。

## 数据和实际消费

官方TransMLA预训练与MQA集按固定revision取小前缀，数据只存E盘。预训练训练集为64个短自然片段加32个QA训练源，开发为16个独立自然片段；QA训练为16个自然源和16个中文反事实U源，开发为8个自然源和8个独立U源。自然QA保留的短答案必须仍在截短的原文中。训练/开发精确源文本去重，不宣称排除语义或底座预训练污染。

RECON读全文，COMP只读前70%–90%单词，但两者都预测整段文本。QA按官方MQA形式串接两轮；中文U的第二轮是同一事实的另一问法，训练时可以看到第一轮gold答案。评测两问均独立生成，因此训练损失不能代替新问题读取能力。

## 自由生成与内容依赖

最终已见和开发各抽8个源/16个独立问题，不是全部训练题验收。原始提示最多生成32 token；表中EM为大小写/空白归一化字符串匹配。下面非零成绩也都通过了严格字符串及EOS检查，但没有把它改称完整精确token基准或M5成绩。

| 最终652态 | 正确载荷 | 关闭载荷 | 替换载荷按原答案 | 反事实两版同时正确 |
|---|---:|---:|---:|---:|
| 已见自然问答 | 1/8 | 0/8 | 0/8 | 不适用 |
| 已见编码题 | 7/8 | 0/8 | 0/8 | 3/4问法配对 |
| 独立自然问答 | 0/8 | 0/8 | 0/8 | 不适用 |
| 独立编码题 | 0/8 | 0/8 | 0/8 | 0/4问法配对 |

已见编码题在替换载荷后7/8跟随另一版真实内容。例如同一实体、同一问题，正确载荷答`Z1-346`，换为反事实源载荷后答`Z1-376`。这支持内容确实经载荷影响答案；独立源编码仍然全部失准。已见/独立自然问答的词级F1分别43.80%/17.17%，自然回答存在部分改写，不能仅凭严格EM抹去这些差异，也不能把部分词重合当精确事实记忆。

同一8题开发子集在初态、预训练末和QA末的memory平均gold NLL：自然5.200→2.916→2.762，编码7.158→3.331→0.998；三代完整EM均0/8。仅看正确前缀损失，会明显高估实际自由生成能力。原始初态还存在思考过程被32-token上限截断的问题，不能用它的plaintext零分声称底座不会读取源文本。

## 提示与新绑定控制

保留所有原始结果，补测同一最终权重、相同4个开发源/8题；使用官方系统提示，及其上增加内容无关的关闭思考前缀，生成上限128。两种条件均有memory/off/foreign/plaintext，不给memory学生原文或答案。

关闭思考后，底座看到原文的独立编码题达到**4/4严格字符串及EOS**，memory仍0/4；对应自然4题plaintext词级F1为71.89%，memory为13.49%，严格EM均0。因而当前新编码失败不能仅归因于思考截断；原文可读、生成载荷读不准的差距仍存在。这是单独提示协议的诊断，没有替换原始32-token成绩或放宽验收线。

在熟悉实体上改变绑定，固定其他源内容并保持问题不变，两问均重新清空cache：

| 内容干预 | 第一问 | 第二问 |
|---|---|---|
| 已见A，原值`Z1-346` | 正确 | 正确 |
| 已见A，改为另一已见值`D0-611` | `D0-111`，错 | `D0-111`，错 |
| 已见B，改为A值`Z1-346` | 正确 | `Z1-643`，错 |
| 已见A，改为未见末位`Z1-347` | 正确 | `Z1-473`，错 |

原绑定2/2，新绑定/新值合计2/6。存在有限的新内容迁移，不是完全常量输出；但同一份新载荷在第一问正确、另一问错误，说明不能把所有失败都简单解释为源信息已经完全丢失。MQA第二轮可能利用第一轮gold答案形成历史捷径，仍需独立单问与多问训练对照确认，不能由此直接宣称“只会复制前一答案”。

## 速度、载荷与完整恢复

| 指标 | 实测 |
|---|---:|
| 已加载、已分词：21源token＋176 memory tokens，首轮写入 | 2.606秒 |
| 后5次热写入中位 | **106.16ms**（94.19–114.73ms） |
| 每条原始FP32因子 | **20185088字节＝19.25MiB** |
| 示例序列化文件 | 20296559字节 |

| 训练峰值allocated/reserved | 7.39/7.90GiB |

热写入计时只包含源编码和M2P，不含模型加载、分词、读答案或磁盘。导出是另一条样本的单独测量，不能相加冒充已实测的完整端到端时延。序列化前后生成完全一致，但所选新绑定样本两次答案都错；工程持久化通过不等于记忆内容正确。

原始因子按每千条约18.80GiB增长，尚不含索引/元数据；长期容量是后续约束。这个载荷约为旧小型生成器432KiB的45.6倍，不能作等容量能力比较。

真实Adam第4态→连续10，对照pause7（Adam1、累积3）→独立进程resume10：**2219个张量、1835701436原始字节、完整payload及样本/损失/账本逐位相同**；每条验证轨迹新消费2080输入。第4态已有真实Adam矩，warmup首步lr0；对照覆盖随后非零lr的实际更新。预训练来源保持不变，SHA相同的最终验证文件只做硬链接去重，未删除完整态。

0.5秒轮询观察：计划pause7边界到下一进程启动约52.17秒（保存被观察到约42.66秒）；冷恢复到首微批完成上界约114.34秒。完整累计状态约1.84GB，比旧模型的暂停/恢复代价高，不能沿用旧7秒暂停数字。该成对轨迹验证覆盖预训练阶段；QA真实57步状态已被后续评测独立载入，但未另做一组成对QA训练轨迹。
